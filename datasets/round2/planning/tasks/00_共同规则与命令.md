## 数量与编号

- A 类材料 = silicate_oxide，600 配方；B 类材料 = iron_rich_oxide，400 配方。成员 A 设计开发 A 类 510，成员 B 设计开发 B 类 340；D 独立设计测试 A 类 90 + B 类 60。
- 成员 A/B/C/D 是人员编号，与材料类别无直接对应。成员 C 生成的 P3 必须同时覆盖两类材料。
- 总主表 1,000 个独立实际采用组成，名义训练/验证/测试为 700/150/150 配方。
- 每个配方在 P1/P2/P3 各两次独立计数噪声；名义训练 4,200、验证 900、测试 900，共 6,000 谱。
- A/B/C 各生成约 850 开发配方在一个条件下的 1,700 谱；D 另做约 300 谱流程试产，并在冻结后生成测试约 900 谱。
- 完整家族优先，数量偏差记录。试产不计新增配方/正式 6,000 谱。
- 不使用旧 C/P5、旧 B/P4，不增加 jitter、不改物理核心、不用重复谱补独立配方。

## 每台机器先确认

- 实际 Python 路径、版本、锁定依赖、生成器源码摘要与团队冻结文件一致；缺失就报告，不默认别人的绝对路径在本机存在。
- 当前计划复用 0.2.1 生成器、0.2.0 物理模型，最终以共同冻结的源码/依赖哈希为准。可从仓库 A 数据归档的 reproducibility 取源码核对，不把旧包当新数据。
- 四人合计新增工作数据的协调存储峰值按 10,000,000,000 字节规划，不是每人各产 10 GB；全量多副本会增加团队总占用，另行记账。
- 用代表试产实测容量及生成/复算秒/谱，不能保证所有组成均为首轮平均大小。
- 代码交付前做语法/编译检查并验证关键正常/失败路径；没有执行的检查明确标 pending。

## 文件契约（待实现并冻结）

个人输出：`datasets/round2/member_A/` 等，不覆盖旧批次。
开发共享文件由 C 维护：`datasets/round2/shared/`。

候选样本使用生成器实际支持的格式：顶层含 `samples`；每个 sample 只含 `id`、`composition_percent`、可选 `provenance`。
`matrix_type`、`parent_family`、`scenario`、`design_owner`、原化合物/ppm、转换/范围依据放在 `provenance` 内，不擅自在 sample 顶层添加字段。
`composition_percent` 是完整采用的元素质量百分数，保留 O 等基体；不是把化合物百分数或 ppm 直接当元素百分数。
共享 registry 以 formula_id 关联样本，索引字段须统一后才生成。

冻结输入至少包括：

- `development_samples.json`：只含训练/验证的约 850 配方；同一文件供 A/B/C 使用。
- `development_split.csv`：formula_id、parent_family、leak_group、matrix_type、benchmark_split、组成摘要。
- `profiles/P1.json`、`P2.json`、`P3.json`：完整字段，不是仅几个覆盖字段。
- `freeze_manifest.json`：源码/依赖、上述文件哈希、32 目标、split_seed、每批独立 batch_id/seed、closure、replicates、无 jitter、预期数量和版本。
- 曝光/覆盖/泄漏检查与四人冻结确认记录。

新测试主表、含真值的组成索引和 full_results 交 D 受限保存，不放开发共享目录或全组可见 PR。公开开发说明可以给测试数量及封存摘要，不公开测试配方或标签。
目录名不是权限隔离；未落实访问保管时只称内部研究测试。设计者可能接触过测试候选，须如实记录，不宣称所有人都未见设计。

## 真实 CLI 的命令模板

以下参数名已按本地 app.py 核对。变量必须替换为本机实际路径与 freeze_manifest 值；这些不是已执行成功的生产命令。
先创建包外报告目录，`$OutputDir` 必须不存在。可在 PowerShell 中设置：

```powershell
# 按实际位置填入，不能原样保留“本机...”字样
$PythonExe = '本机锁定环境的python.exe绝对路径'
$GeneratorApp = '本机冻结版本app.py绝对路径'
$SamplesFile = '本机冻结development_samples.json绝对路径'
$ProfileFile = '本机冻结P1或P2或P3.json绝对路径'
$OutputDir = '本机不存在的新批次目录绝对路径'
$AuditOut = '包外且不存在的audit.json绝对路径'
$ReplayOut = '包外且不存在的replay.json绝对路径'
$ZipOut = '包外且不存在的归档.zip绝对路径'
# $BatchSeed 与 $SplitSeed 从 freeze_manifest 读取，不自行猜测
$env:OPENBLAS_NUM_THREADS = '1'
$env:OMP_NUM_THREADS = '1'
$env:MKL_NUM_THREADS = '1'
$Targets = 'Na Mg Al Si P S Cl K Ca Ti V Cr Mn Fe Co Ni Cu Zn As Se Rb Sr Y Zr Nb Mo Cd Sn Sb Ba W Pb'.Split(' ')
& $PythonExe -B $GeneratorApp batch --samples $SamplesFile --profile $ProfileFile --replicates 2 --seed $BatchSeed --split-seed $SplitSeed --closure strict --legacy-al reject --targets $Targets --out $OutputDir
if ($LASTEXITCODE -ne 0) { throw 'Generation failed; stop and retain evidence' }
```

使用该批实际封存源码的 app.py 做审计/重算。设 `$SnapshotApp` 为 `$OutputDir/reproducibility/generator/fp_competition/app.py` 的实际路径：

```powershell
& $PythonExe -B $SnapshotApp audit --dataset $OutputDir --out $AuditOut
if ($LASTEXITCODE -ne 0) { throw 'Audit command failed' }
& $PythonExe -B $SnapshotApp replay --dataset $OutputDir --out $ReplayOut
if ($LASTEXITCODE -ne 0) { throw 'Replay command failed' }
# 必须再读取报告判定，而非只看进程退出码；passed_with_environment_differences 需保留差异并按团队规则审核
# 确认全量 audit/replay 与独立交叉复核放行，再打包；pack 自身不会代替全物理重算
& $PythonExe -B $SnapshotApp pack --dataset $OutputDir --out $ZipOut
if ($LASTEXITCODE -ne 0) { throw 'Pack command failed' }
```

生产者和复核者都做全量 replay，不传 `--limit`。读 report：errors 为空、覆盖全批、计数一致、浮点容差符合冻结标准；环境差异单列，不改写 sealed manifest 掩盖差异。
检查过程中失败就保留失败身份，以新版本修复，不删除坏谱或直接改结论为 passed。

## 每个批次的最小交付

- 密封批次或 ZIP、外部 SHA-256、CRC 检查记录；保留 blind_inputs、truth、full_results、inputs/configs、manifest/integrity、源码和依赖快照。
- 包外完整 audit/replay、命令、退出码、实际时间、运行环境与解释，不仅交截图。
- `production_record.json`：批次身份、输入哈希、seed、数量、版本、用途、状态；`review_record.json` 由另一位成员填写。
- 全局索引必须逐谱关联 batch/local/global ID、配方、家族、条件、generator_split、benchmark_split、盲/完整结果双哈希；实际生成后补齐 ID/哈希，不预造不存在的谱。
- 文件传递只给指定复核人；不要让协调人保存四人所有解包副本。新测试包只在冻结后给 B 复核，不发开发组。

## 团队顺序

共同冻结设计规则和范围 → A/B 设计 850 开发候选、D 独立设计受限 150 测试候选 → C 受限合并核查、形成只读开发导出 → D 独立检查 → 四人冻结摘要 → D 试产/C 复核 → A/B/C 开发生产和交叉复核 → A 冻结模型 → D 测试出谱/B 复核 → D 评分。
生产复核环：A 审 B/P2、B 审 C/P3、C 审 A/P1；D 试产由 C 审，D 新测试由冻结后的 B 审。自己的自检不算另一人复核。
缺少上游冻结输入时，先交缺项清单与可完成的设计资料，不擅自扩大任务、猜 profile 或自行另建一份“最终主表”。
