# 成员 A：510 硅酸盐开发配方、P1 开发谱、模型冻结

请同时阅读 `00_共同规则与命令.md`。人员 A 不等于只处理 A 类材料。

## 你先拿到什么

- 协作仓库访问与同一版本生成器/依赖；首轮曝光索引、首轮模型/评估。
- 原 A 类设计范围作为候选依据：仓库 `datasets/round1/A-part-20261018/A_design_ranges.json`。常规 SiO2 平衡 25–85%，Fe2O3T 1–20%，单位是化合物质量百分数；不是所有特殊情景的强制范围。
- 个人目录 `datasets/round2/member_A/`，所有新版本使用新目录。

## 第一阶段：设计 510 开发配方（先共同冻结设计规则）

- [ ] 提交常规 306、稀疏/边界 104、完整干扰对照 100，共 510 个不同的实际采用组成。另 90 个 A 类测试配方由 D 独立设计，你不接收其组成；两者相加才是本轮 A 类 600。
- [ ] SiO2 补足，保留组分/ppm 输入和元素转换，严格闭合；常规与特殊情景范围、平衡组分/例外逐项登记。
- [ ] 覆盖 Si/Al/Fe 主量变化，Sb 和其他目标零/低含量、As/Pb 与 S/Pb 对照；不得把化合物加入引起的多元素变化说成单变量。
- [ ] 给每条配方唯一 ID；元数据放 provenance，matrix_type=silicate_oxide，登记 parent_family；噪声重复、改名或换 profile 不算新增配方。
- [ ] 已知近邻/衍生/干扰族全部登记，向 C 提交首轮来源与曝光关联。无法确认未暴露就不声称可作为新盲测。
- [ ] 自查实际组成去重、闭合/范围/对照逻辑和覆盖；缺口如实列出。

交给 C：`candidate_samples_A.json`、`formula_registry_A.csv`、`design_ranges_A.json`、`coverage_A.json`、`design_checks_A.json`、可复现构建脚本及运行/编译记录。个人目录内写 README、文件哈希清单。C 如退回重复/越界/缺口，补新版本，不私自覆盖旧证据。

## 第二阶段：P1 开发生产（等冻结及试产放行）

- [ ] 领取 C 的同一 `development_samples.json`（约 850 配方，同时含两类材料）、开发划分、冻结 P1 与 seed/hash 清单。
- [ ] 核对冻结摘要，使用共同命令模板 batch：P1、replicates=2、无 jitter，约 1,700 谱。
- [ ] 全量 audit/replay，保留封存原件及包外报告、环境、命令、时长/容量；自检通过交 C 独立复核。
- [ ] 收 C 的复核记录，问题保持失败身份，用新批次修复。
- [ ] 接收 B/P2，核对来源和 ZIP/内部双哈希，使用 P2 包内源码在自己环境全量 audit/replay；输出独立 `review_record` 给 B 和 D。

## 第三阶段：开发训练与冻结

- [ ] 只有三个开发批次都放行且权威索引映射完整，才按 benchmark_split 读训练/验证；不用各批 generator_split 直接拼训练集。
- [ ] 只用计数作为预测输入，truth 用于监督/评分；profile/真实能量轴/无噪声分量不偷偷当未知条件任务的特征。
- [ ] 保留首轮 Ridge 对照，只用训练/验证选特征和参数；逐元素与基体/profile 分层，不只报总平均。
- [ ] 冻结后交 D：模型、预测程序、预处理/目标/单位、依赖、模型与代码哈希、训练记录及固定评分协议。
- [ ] 不接收新测试标签/full_results，不根据测试分数继续调参；若继续开发，必须承认该测试已曝光。

验收：510 独立开发候选（退回修改闭环）、P1 全量工程复核、B/P2 独立复核记录、开发-only 训练与可重载模型、冻结材料齐全。数值复现不等于真实定量准确度。
