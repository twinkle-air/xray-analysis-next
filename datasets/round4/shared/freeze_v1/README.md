# 第四轮公共冻结审查版

当前是已准备完整输入、等待协作者审查的冻结版本。生产 release 尚未批准，实际能谱为 0，不安排试片。完整输入经审查后可按 A 40,000、B/C/D 各 20,000 的配额一次生产。

## 已落实的输入

- `global_closure.json`：5,000 个唯一组成、1,600 个设计族，结合全部原始底板，对 7,517 个已登记不同历史组成作全局亲缘检查。没有跨族或历史 L1≤0.5 个百分点的连接；未知历史祖源仍未被排除。
- `family_assignments.json`：整族用途为 80,000 训练、10,000 验证、10,000 封存谱；stage1/2/3 是训练队列，增量 20,000/20,000/40,000，累计 20,000/40,000/80,000。候选中的 requested_role 和 pending 历史标记不是权威分配。
- `profiles/`：50,000 个条件实例，每个组成 10 个真实不同的配置，每个配置配两条不同噪声种子的谱。开发配置和封存配置分别存放；500 个封存组成各有 5 个分布内和 5 个未见响应区间条件。
- `record_plan_A.csv` 至 `record_plan_D.csv`：100,000 个全局记录 ID、opaque 盲 ID、条件和噪声种子；`batch_plan.json` 将它们编排成 1,000 个约 100 谱的原生批次，A 400 批，B/C/D 各 200 批。原生批次 split 不作为训练用途。
- `generator/fp_competition/`：包装层版本 0.2.2；只扩展每个输入条件显式指定完整 profile 的能力。物理核心 0.2.0 和化合物换算保持原字节。两次噪声重复复用同一完整 profile。

## 条件的来源与限制

开发条件以 P1/P2/P3 为锚点，扰动幅度来自此前 D1～D6 的假设敏感性设计。增益、零点、电子噪声、曝光和出射空气路径连续采样；部分外侧参数区间专留封存响应挑战。旧 T1～T3 不复用为新条件，也不进入训练或响应字典。

滤片、本底常数、探测器窗厚、几何与质量厚度沿用锚点，未新增经过实测校准的分布；粒度、湿度、容器效应没有通过改元数据冒充模拟。所有 profile 仍是 `assumed_unverified`。本轮只能支持该明确范围内的合成方法研究，不能据此证明真实设备精度。

## 无产谱核验

`independent_static_verification.json` 全量核对 100,000 条计划和 50,000 组条件、整族用途、已知 8,400 条历史噪声种子、封存参数隔离、十组条件的实际差异以及两次重复的响应一致性。旧版普通输入的抽样计划摘要与新包装层一致，四种无效输入被拒绝。没有进行正演试片。

实际生产中的每一条谱仍须通过六分量与窗口账目检查，并对本人完整配额做一次全量 audit/replay/QC。`window_budget.json` 沿用预注册阈值，失败谱和日志保留，不放宽预算或删除合法极端谱。

`resource_budget.json` 从第三轮既有原档读取压缩/展开字节作线性估算；含展开工作副本时，A 约需 53.8 GB、其他成员各约 26.9 GB，再加空闲空间保留。估算不是容量保证，执行器在生产前和每批次检查实际磁盘空间。

## 下一步

按 [生产工具说明](../production_tools/README.md)运行无产谱预检。依据仓库 CONTRIBUTING，新的生成器包装层和执行器须由另一位协作者审查；合并并登记审查证据后，由 A 核对输入/工具哈希并批准完整生产 release，再执行本人全量命令。

封存谱始终只用于生成/QC及后续锁定模型后的评价，不能用于训练、校正拟合、字典或选参。共享仓库中的配置与真值不构成对全队不可见的独立外部盲测。
