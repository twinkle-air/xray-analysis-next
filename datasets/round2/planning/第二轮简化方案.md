## 只保留四步

1. **你统一发规则和输入版本**：确定生成器/依赖及三个完整 profile 的哈希、范围、32 目标、样本格式和种子清单。各成员先提交自己的 250 候选配方及母族、组成/转换账目、范围和覆盖自检。你合并检查跨成员重复和已知亲缘；不足退回补足。全局确认前不直接批量出谱。
2. **各成员构建并自检一次**：领取自己经你确认的配方，依次生成三个条件，每条件 500 谱。各人可先做自己的一小片确认正常再继续，不需要你逐片审批；已做小片属于最终 1,500 谱，不另算额外试产。所有分片分别封存、ID/seed 唯一，不能向已密封目录追加。小片选取保留完整家族。
3. **他们交给你统一复核**：每个人自行完成全包 audit 和全量物理 replay，不传 --limit。检查计数、标签、范围、六分量和窗外账目、双哈希及全部谱覆盖，提交实际报告。B/C/D 不互相复核、不接其他人的谱任务。你只按下方四项核对，不重复全量物理 replay；异常才追加定位检查，失败退回本人修复新版本。
4. **你合并、划分、训练**：只收实际复核通过的谱；把相同组成、parent_family、生成器族及已知近邻取连通组，约 70/15/15 分为训练/验证/内部研究测试。三个条件和噪声重复跟随同一家族。使用外置权威索引，不改 sealed truth/manifest，也不把各人的 generator_split 直接拼起来。

全局家族用途可以在配方确认时确定，生成后再补谱 ID/哈希映射；具体数量因整族划分略偏，报告配方、家族、谱数。名义训练/验证/测试为 4,200/900/900。
你作为协调/复核者会接触全部数据，本版明确采用内部按家族留出评估，不再宣称独立保管人盲测。测试行仍不参与拟合、预处理拟合或选参；一旦用测试反馈改方案，登记其曝光。首轮曝光亲缘不进入新的“未见家族”集合，无法保证时降级说明。
A 自检不称另一人独立复核。本轮不再要求四人交叉签署；不虚构外部独立验收或真实设备准确度。

## 自检命令的最低要求

实际运行路径、batch seed、split seed 由你统一发放。生成器真实命令为 batch --samples ... --profile ... --replicates 2 --seed ... --split-seed ... --closure strict --legacy-al reject --targets ... --out ...，不传 --jitter。输出必须是新目录。
每个批次使用其实际封存的 reproducibility/generator/fp_competition/app.py：

```text
python -B <封存app.py> audit --dataset <批次目录> --out <包外audit.json>
python -B <封存app.py> replay --dataset <批次目录> --out <包外replay.json>
python -B <封存app.py> pack --dataset <批次目录> --out <包外新归档.zip>
```

尖括号为待替换项，不能原样执行。先检查报告通过再打包；只看进程退出码不够，pack 不代替物理 replay。errors 为空、全量覆盖、计数一致且浮点满足冻结容差；环境差异保留说明，不篡改原报告。
构建/校验代码交付前编译或语法检查并复核关键正常/失败路径。未知参数、缺源码或错误不能靠猜补齐。

## 存储

6,000 谱原始文件按首轮均值估计约 6.52 GB；约 10 GB 是本轮协调工作集峰值目标，需计入 ZIP、源快照、报告、模型与中间文件。所有成员机器上的冗余副本另外记账，不能声称全团队多副本仍只占 10 GB。
先测代表小片大小，超预算先减少未生成的完整家族或移存已验证归档，不删 full_results/truth、跳过复核或选择性丢弃困难谱。没有实现过的自动容量保护不标已完成。
你一次接收和复核一个成员，避免在协调机多次解包同一份全量数据；删除任何唯一原件前先确认可恢复归档。
