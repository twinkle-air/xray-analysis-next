## 第一阶段：主表、分组与冻结

- [ ] 在受限环境核对 850 开发候选与 D 的 150 测试候选共 1,000 条，按真实采用的完整元素组成去重，不按名字去重；保留完整基体。精度/规范化口径与首轮一致或明确版本变化。
- [ ] 同组成跨 A/B、同母族、生成器 family、已声明近邻/衍生关系取连通闭包；不能只用原生精确组成 family。
- [ ] 写曝光台账；首轮曝光配方及已知亲缘只能作开发/历史回归，不进入新家族测试。若无法证明未曝光，标记并退出新盲测候选。
- [ ] 在 A/B 的 850 开发候选中按基体/情景分层分配约 700 训练、150 验证；D 的 150 候选只作新家族测试，若与开发/首轮曝光有精确或已知亲缘关联，退回 D 重设计，不把这些行交换到开发端。整族分配，偏差报告。不得拆同族凑数量。
- [ ] 交 D 独立核对，接受回退；不足 1,000 个独立组成/覆盖不足，按开发候选退回 A/B、测试候选退回 D 补充，不用重复谱补数。
- [ ] 冻结输入主表、范围、profile、代码/依赖哈希、seed、目标列表和版本，取得四人确认记录。
- [ ] 向 A/B/C 开发端只发约 850 开发配方/划分；测试主表、真值组成索引和身份映射仅交 D 保管，不放 shared 或全组可见 PR。

交付：`master_samples`（受限全表）、开发导出、`formula_registry`、`exposure_ledger`、`global_split`、覆盖/去重/泄漏检查、冻结 manifest。自己接触过测试设计需记录，并且不参与利用这些设计的模型调参。

## 第二阶段：试产复核与 P3 开发生产

- [ ] D 的约 300 试产谱完成后，使用其封存源码和锁定环境做全量 audit/replay，确认所有条件、完整家族、双哈希、实际标签、六分量和窗外账目。
- [ ] 试产复核/容量预算未放行前，不启动 P3 全量生产。
- [ ] 领取同一约 850 开发样本与冻结 P3/seed，生成两次噪声约 1,700 谱；自检后交 B 独立复核。
- [ ] 接收 A/P1 独立全量复核，记录原包哈希、完整重算覆盖、错误/差异和环境，结果交 A/D。
- [ ] 各批实际生成后才组装 authoritative_index，核对全部约 5,100 开发谱与 truth/manifest：ID 唯一、映射一一对应、条件与配方匹配、盲/完整结果摘要正确、generator_split 与 benchmark_split 分开。
- [ ] 为读取入口做实际失败路径检查：测试/隔离行不得进入训练；相同组成/母族/重复/跨 profile 不跨集合。

生产时禁止用全表原生 split 代替统一权威用途；分片原生 split 不一致时也不得改 sealed 文件迁就。新增索引/校验代码须编译并做关键失败用例检查。
