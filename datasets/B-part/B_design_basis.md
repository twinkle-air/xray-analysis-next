## 1. 矩阵定位与"富铁"判据

B 的矩阵是**富铁氧化物**：以 `Fe2O3T` 作为**主平衡组分**（balance compound），脉石氧化物只占
次要质量。这与 A 的硅酸盐-氧化物矩阵（SiO2 平衡、Fe2O3T 1–20%）在结构上相反，不是把 A 的
设计换个名字：A 的平衡相是 SiO2，B 的平衡相是 Fe2O3T，因此两者的 Si/Fe 标签分布、基体吸收和
谱线增强关系都不同。

判据在抽样之前声明，并对**每一条**配方逐条检查（`make_row()` 内的 `iron_rich_check`，
`B_coverage.json` → `iron_rich_criterion_verification`）：

1. `Fe2O3T ∈ [40, 75]` 质量百分数（按 Fe2O3 化学计量假设折算为元素 Fe ∈ [27.977, 52.458]%）；
2. Fe 严格大于其余 31 个候选靶元素中的任何一个；
3. 元素质量分数之和按**严格闭合**（`closure='strict'`，容差 1e-6 个百分点）等于 100%；
4. 每个化合物用量、每个痕量用量都落在 `B_design_ranges.json` 声明的区间内（痕量允许显式 0）；
5. 脉石总量（非 Fe 化合物 + 痕量折算）∈ [25, 60]%，由第 1 条等价推出，单独记录便于定位。

实测结果：1,500/1,500 条通过全部布尔判据；`Fe2O3T` 实际范围 40.0–75.0；闭合误差最大
1.42e-14 个百分点。**没有采用任何非严格闭合的决定**，因此也没有相应的例外记录。

`Fe2O3T` 是全铁 Reporting 约定（转换时按 Fe2O3 化学计量假设），**不是**对铁价态或氧含量的测量
结论；这一句来自交付生成器自带的 provenance note，B 未改写。

## 2. 设计范围与理由

区间值是为**标签覆盖**人工设定的实验设计值，不是矿种统计、不是检出限、不是 Certified 参考值。
所有区间的下界为 0 的化合物都允许"精确不存在"。

| 化合物 | 区间 % | 载着的靶元素 | 设定理由 |
|---|---|---|---|
| Fe2O3T | 40–75（平衡项） | Fe | 富铁基体本身，必须同时是全谱最强元素之一并可覆盖高/低两端 |
| SiO2 | 0–25 | Si | 最常见的脉石；上限保证能与任一种闭合组合共存 |
| Al2O3 | 0–20 | Al | 粘土/长石类脉石 |
| CaO | 0–14 | Ca | 碳酸盐/硅酸盐脉石；与 CaSO4 共变 Ca |
| MgO | 0–12 | Mg | 白云石/橄榄石类脉石 |
| TiO2 | 0–3 | Ti | 钛铁矿类副矿物，弱线区压力点 |
| MnO | 0–4 | Mn | 锰副矿物，Mn K 线在富铁基体中受吸收 |
| P2O5 | 0–1 | P | 磷灰石微量，低 Z 弱线 |
| K2O | 0–2 | K | 长石/云母 |
| Na2O | 0–2 | Na | 长石；与 NaCl 共变 Na |
| CaSO4 | 0–3 | S（并带 Ca、O） | 硫酸盐脉石；S/Pb 干扰块的唯一硫源 |
| NaCl | 0–0.5 | Cl（并带 Na） | 可溶盐污染情景，轻元素线系压力点 |

20 个痕量元素（V、Cr、Co、Ni、Cu、Zn、As、Se、Rb、Sr、Y、Zr、Nb、Mo、Cd、Sn、Sb、Ba、W、Pb）
区间 1–1,200…4,000 ppm，精确 0 的概率统一设为 0.25。上限按"在富铁氧化物里作为副矿物/污染可
出现的量级"人工设定，并保证每个痕量元素的声明最大值折算成元素百分数后**高于低值箱上限 0.1%**
（最小的 Cd 为 1,200 ppm = 0.12%），否则高值箱在定义上不可能被达到。

`B_design_ranges.json` 就是交付 CLI `design-mineral` 实际读取的文件（SHA256 记在
`B_coverage.json → design_manifest`），不是事后另写的一份说明。

## 3. 分块构造算式（900 / 300 / 300）

| 块 | 条数 | 构造方式 |
|---|---|---|
| routine | 900 | 交付 CLI `design-mineral` 在声明区间上均匀抽化合物、log-uniform 抽正痕量、25% 显式缺席、Fe2O3T 平衡且仅在接受带内保留；池种子 2026101821，池大小 1,000，取前 900 |
| sparse_exact_zero | 132 | 6 个旋转闭合对 × 22 族，每族的"零行"：除闭合对与 Fe2O3T 外所有化合物显式不存在，20 个痕量全部显式 0 |
| sparse_low | 132 | 同一 132 族的"低值兄弟行"：Fe2O3T 与闭合对保持不变，把尖峰质量从较大的那个载体扣掉，其它每个非载体氧化物元素注入 0 < x ≤ 0.1%，每个痕量注入 1–1,000 ppm（= 0.0001–0.1%） |
| declared_maximum_spike | 31 | 每个适用元素一行，钉在其声明最大值（化合物取其载体上限、多载体取全部上限；痕量取其 ppm 上限），其余为正常多氧化物背景 |
| boundary | 5 | `balance_upper`（Fe2O3T=75）、`balance_lower`（Fe2O3T=40）、`all_traces_max`（20 痕量同时取上限）、`all_traces_min`（20 痕量同时取 1 ppm）、`two_carrier_ceiling`（最宽闭合对两个化合物同时取上限且痕量全缺席） |
| interference | 300 | 60 族 × 5 对照；As/Pb 与 S/Pb 各 30 族；对照 = 双零 / 仅前者 / 仅 Pb / 双 1× / 10:1 |

算式：900 + (132×2 + 31 + 5) + 300 = 900 + 300 + 300 = 1,500；脚本用 `assert` 硬约束稀疏块
恰为 300 行，任何块数偏差都会在生成阶段直接失败，而不是靠事后删补凑数。

**低值箱定义**：`0 < 元素质量百分数 ≤ 0.1`。这是本设计采用的初始统计报告约定，**不是检出限**，
也不声明真实样品能否测到。**零的定义**：该配方不加入任何携带该元素的化合物或痕量；不是"实际
不含"。中/高箱以该元素的**声明最大值**为中点判据：mid = 0.1 < x ≤ max(0.1, 0.5×声明最大)，
high = x > 同一分界。声明最大值由 `B_design_ranges.json` 通过交付转换器换算到元素口径得到，
不手工填写。

## 4. 为什么用旋转闭合对（对 A 的 Si 缺口的回应）

A 的 `A_coverage.json` 显示 Si 的 zero/low 两箱为 0（`gaps.Si`），原因是 SiO2 是唯一平衡载体，
Si 在结构上不可能为 0 或低值。B 若只用 SiO2 闭合会重现同样缺陷，且 Al 也会失去低值通道。
因此稀疏块用 6 个两两组合轮换承担脉石质量：

| 闭合对 | 载体上限之和 % | 可满足 ≥25% 脉石下限 | 可让哪些元素为零/低 |
|---|---|---|---|
| SiO2 + Al2O3 | 45 | 是 | Ca、Mg、Ti、Mn、P、K、Na、S、Cl 及全部痕量 |
| SiO2 + CaO | 39 | 是 | Al、Mg、… |
| SiO2 + MgO | 37 | 是 | Al、Ca、… |
| Al2O3 + CaO | 34 | 是 | Si、Mg、… |
| Al2O3 + MgO | 32 | 是 | Si、Ca、… |
| CaO + MgO | 26 | 是 | Si、Al、… |

每个元素在 3 个对中作载体（不可能为零），在另外 3 个中不作载体（零行给出 3×22=66 个零，低行
给出 3×22=66 个低值）；不是载体的元素在全部 6 个对里都参与（6×22=132 零 + 132 低）。实测每个
适用元素的零值不少于 66、低值不少于 66，达到任务卡"争取至少 50/50"的要求，因此**没有需要
申报的 <50 缺口**（`B_coverage.json → gaps` 中 `shortfall_counts` 全为空）。

## 5. 复合载体共变：如实记录，不假装单变量

- **S 只能通过 CaSO4 引入**，所以 S/Pb 干扰族的 S 变化必然带动 Ca 与 O。以 B-I0030 为例：
  S = 0 → 0.04711% → 0.47110% 时，Ca = 3.32173% → 3.38060% → 3.91049%，O = 38.04834% →
  38.08224% → 38.38134%。全部 30 个 S/Pb 族的 Ca 观测范围 0.347–10.164%。这一共变已写入每条
  配方 `provenance.design_detail.sulfur_note`，并在 `B_coverage.json` 的按场景统计中体现。
- **Cl 通过 NaCl 引入会带动 Na**；**Na 有两个载体**（Na2O、NaCl），**Ca 也有两个载体**
  （CaO、CaSO4）。低值注入按化合物换算并同时受"同一化合物里另一个被跟踪元素"的余量约束，
  因此不会出现为了压低 S 而把 Ca 顶出 0.1% 的情况。
- 痕量元素与化合物载体元素无重叠（V…Pb 均不由氧化物携带），交付转换器对"化合物里已存在的
  痕量元素"会直接报错，B 的范围表刻意避开了这种冲突。

## 6. 去重双判据、近邻阈值与合并

两条判据同时列出并同时满足：

1. **A 规则**（与 `build_A.py` 一致）：`SHA256(json.dumps({非零元素: 百分数}, sort_keys=True))`；
2. **统一数值规则**：33 个符号固定顺序（32 个靶元素 + O）取值四舍五入到 12 位小数后取
   `SHA256(json.dumps(vector))`，从而把"只是零元素是否出现在字典里"的差异也合并。

**近邻判据与方法**：在同一个 33 维向量上取 L∞ 距离（绝对元素百分点），阈值
`≤ 0.10` 判为近邻；用 union-find 做传递合并，规范名取最小族标签（确定性）。近邻的
扰动/增强/对照行共享同一 `parent_family`。

实测：1,500 条在两条判据下都是 1,500 个唯一值（`resolve_duplicates()` 的固定补足规则——
MgO +0.0001×序号、Cd +1 ppm、Fe2O3T 重新平衡——**一次也没有触发**，`B_recipe_checks.json →
duplicate_repairs = []`）；跨族近邻对 39 个，27 行被改写到规范族名下；合并后族数 1,120，
规模直方图 `{1:945, 2:110, 3:2, 4:1, 5:61, 20:1}`。60 个干扰族全部保持 5 行完整
（`interference_families_of_size_5 = 60`），没有任何族跨场景
（`families_spanning_scenarios = []`）。含 20 行的最大族是稀疏块传递链的结果，已在
`largest_family_evidence` 中列出成员与原因；它只会让全局按族划分更保守，不会把同一个 5 行
对照组拆到不同折。

阅读直方图时注意：规模 5 的族有 61 个，其中 60 个是干扰族，另外 1 个（`B-S0118`）是稀疏块
传递合并出来的 5 行链，**不是**干扰族被拆开；27 个被改名的行全部属于 `sparse_boundary` 场景。

## 8. 缺口与原因（未凑数）

`B_coverage.json → gaps` 列出 13 个元素：Co、Ni、Cu、As、Se、Rb、Y、Nb、Mo、Cd、Sn、Sb、W。
它们的 `shortfall_counts` 为空（零与低值都 ≥ 400/900 量级），唯一原因是
**`band_definition_degenerate = true`**：这些元素的声明最大值 ≤ 0.2%，其一半 ≤ 0.1%，与低值箱
上限重合，所以 mid 箱 `(0.1, max(0.1, 0.5×上限)]` 在定义上是退化区间，mid = 0 是定义后果，
不是覆盖失败（这些元素的 high 箱都有 15–101 条）。B 选择**如实标注**，不为了填满 mid 而临时
放宽这些痕量的上限——那会改变设计口径，需要重新与 A/C 对齐。

另外两条需要下游知道的结构性事实：routine 与 interference 块不承诺逐元素零/低配额（前者随机、
后者是对照结构），承诺只来自稀疏块构造，证据见 `block_construction_proof.per_block`。

## 9. 与 A 的交叉重叠

`B_cross_A_overlap.json` 用同一把尺子（两条去重判据 + L∞ 近邻）比对 A 的 2,500 条主配方：

- 两条判据下的**精确重叠均为 0 条**；
- 在 0.00 / 0.05 / 0.10 / 0.50 / 1.00 / 5.00 五个阈值下**计数全为 0**；
- 最近的 A 邻居距离 13.996 个百分点（B01197 ↔ A01421），Top-10 全部 ≥ 13.99；
- `formula_id` 与 `parent_family` 均无碰撞（B 用 `Bxxxxx` / `B-R####`、`B-S####`、`B-I####`、
  `B-H-<tag>`；A 用 `Axxxxx`）；
- 结论与机理一致：A 以 SiO2 平衡、Fe2O3T 1–20%，B 以 Fe2O3T 40–75% 平衡，二者若出现精确或
  近邻碰撞本身就是设计错误，因此仍把距离全量记录（每条 B 配方的最近邻都在文件里）。
- **B 不修改 A 的任何配方**；该清单交给 A 做 5,000 行主表合并。

## 10. 已知限制

1. 全部为合成设计值，不代表任何真实矿种分布，也没有证认/ certify；
2. 富铁判据里的"Fe 最大"是**候选靶元素之间**的比较，O 由化学计量决定，可能高于 Fe，这是记账
   而非靶标签；
3. `parent_family` 只在 B 内部有意义，全局 train/validation/test 划分仍 pending（`split_status`
   列全部写 `pending_global_5000_family_split`），因为 5,000 行主表与 C 的权威索引还不存在；
4. 交付的 `design-mineral` 拒绝任何区间外取值，因此池内 1,000 条本身已被平衡带筛选（拒绝采样，
   上限 `count*100+1000` 次尝试）；B 未修改该逻辑；
5. 单人自检不等于 A 对 B 的交叉复核：本设计仍需 A/C 复核，`B_preflight.json` 与 README 都把
   cross-person review 标为 pending。

## 11. 复现

在 B 的冻结解释器上（`B_environment.json`），线程变量按记录钉为 1：

```
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 NUMEXPR_NUM_THREADS=1 \
<venv313>/Scripts/python.exe -B datasets/B-part/build_B.py
```

脚本会：写出 `B_design_ranges.json` → 以固定种子调用交付 `app.py design-mineral`（日志
`work/design_mineral_cli.log`，并与进程内 `design_minerals` 逐条比对前 3 条）→ 构造四个块 →
近邻合并 → 去重补足（若触发）→ 逐条与全量校验 → 写出五份产物。种子：构造
`DESIGN_SEED=2026101820`，池 `POOL_SEED=2026101821`（都不等于 A 的正式批种子 2026101801/02，
也不等于为 B 正式预留的 2026101803/04）。重跑得到完全相同的汇总（本次已在同环境复算两次，
族数、覆盖与重叠逐项一致）。
