# 协作约定

## 任务与分工

一个 Issue 描述一个可验收任务，列明问题、负责人、涉及模块、验收标准和依赖。建议数值分析与网页分别设主要负责人；输入输出契约、科学边界和发布共同审查。开始修改同一核心文件前先协调。

## 日常流程

```bash
git switch main
git pull --ff-only
git switch -c feat/your-task
# 修改后执行项目已约定的必要检查
git add path/to/changed-file
git commit -m "描述具体修改"
git push -u origin feat/your-task
```

在 GitHub 创建 PR 并关联 Issue，说明修改、验证和限制，由另一人审查。合并后双方同步 main。不要向 main 强制推送，不提交账号认证信息。

## 审查标准

- 修改与任务范围一致，输入输出接口变化已说明。
- 代码交付前完成适用的编译或语法检查，并验证关键行为及失败路径。
- 数值、单位、缺失条件和不确定性不可由模型猜测补齐。
- 测试结果与科学验证的适用边界明确。
- 无私人数据、密钥、环境目录或临时文件。

没有源码和技术栈时不预设虚假的测试命令；选型后在 README 固定真实命令，再配置 CI。
